# INSTALL_AGENT.md — протокол развёртывания pi harness v2

> Ты — **архитектор**. Рядом с этим файлом лежит архив `pi-harness-dist-20260630.tar.gz`
> (pi harness v2, аудит `A-01..A-36`). Распакуй его и разверни по протоколу ниже.
> Владелец уже положил и архив, и эту инструкцию в одну папку — они рядом.

## Цель

Развернуть обновлённый харнесс (v2) поверх старой v1, **сохранив память проекта**
(`<project>/memory/`). После развёртывания ты (архитектор) должен заработать в том же
контексте, что и до обновления.

## Протокол развёртывания

0. **Распакуй архив** (он в той же папке, что и этот файл):
   ```bash
   cd /папка/где/лежит/этот/файл
   tar xzf pi-harness-dist-20260630.tar.gz
   ```
   Появится директория `pi-harness-dist/`:
   ```
   pi-harness-dist/
   ├── global/                      # → ~/.pi/agent/
   ├── project-template/            # шаблон для нового проекта (тебе вряд ли нужен)
   ├── scripts/install_from_archive.sh
   ├── README.md
   └── INSTALL_AGENT.md             # копия этого файла
   ```

1. **Проверь окружение.** Если чего-то нет — сообщи человеку и **НЕ продолжай**:
   - pi установлен? `which pi` (должен вернуть путь).
   - node 22+? `node -v`.
   - python3 ≥ 3.10? `python3 --version`.
   - clipproxy доступен? `curl -sS --max-time 5 http://CLIPPROXY_HOST/v1/models`
     — вернёт `401` если прокси жив (connection refused / timeout = недоступен).

2. **Определи путь проекта** — директорию, где лежит память проекта (`<project>/memory/`).
   Спроси у человека, если не ясно.

3. **ЗАПУСТИ установку:**
   ```bash
   bash pi-harness-dist/scripts/install_from_archive.sh <project_path>
   ```
   Скрипт сделает: бэкап старой v1 (`~/.pi/agent.bak.<timestamp>`) → скопирует `global/`
   в `~/.pi/agent/` → создаст `~/.pi/agent-memory/` → сохранит (или инициализирует из
   template) память проекта → выставит `chmod 600` на секреты → верификацию.

4. **Проверь результат:**
   - Агентов 13: `ls ~/.pi/agent/agents/*.md | wc -l` → `13`.
   - Навыков 9: `ls ~/.pi/agent/skills/` → 9 директорий.
   - Секреты `600`: `ls -la ~/.pi/agent/auth.json` ( `-rw-------` ).
   - JSON валиден: `python3 -c "import json; json.load(open('$HOME/.pi/agent/models.json'))"`
     (молчание = OK).

5. **НЕ трогай** `<project>/memory/` — это чужая память. Скрипт уже её сохранил.

6. **Health-check.** Запусти `pi` и выполни `/health`. Если pi нельзя запустить прямо сейчас —
   проверь напрямую валидность `models.json` / `settings.json`.

7. **Перезапусти pi**, если он был запущен в другой сессии, — чтобы подхватить новый
   `~/.pi/agent/`.

8. **Отчитайся человеку:** что установлено (agents=13, skills=9), где бэкап
   (`~/.pi/agent.bak.<timestamp>`), что НЕ тронуто (`<project>/memory/`), статус health.

## Edge cases

- **(a) pi не установлен** → сообщи человеку, остановись. Установка харнесса без pi бессмысленна.
- **(b) clipproxy недоступен** → сообщи (секреты переданы, но LLM-доступа нет; `/health` будет
  падать на моделях). Харнесс можно поставить, но работать без прокси не будет.
- **(c) старой v1 нет** (`~/.pi/agent/` отсутствует) → чистая установка, бэкап не нужен.
- **(d) проект без `memory/`** → скрипт создаст `memory/` из `project-template/memory/`.
- **(e) конфликт версий config** (`models.json`, `settings.json`, `config/*`) → новые файлы
  перезапишут старые; старые останутся в бэкапе `~/.pi/agent.bak.<timestamp>/`.
- **(f) WARN «агентов 14 вместо 13»** → в старой v1 были кастомные агенты (с другими именами);
  `cp -a` поверх не удаляет не-совпадающие файлы. Старая v1 целиком в бэкапе. Проверь
  `ls ~/.pi/agent/agents/` и удали orphan-агенты из v1, если они не нужны (или оставь —
  откат возможен из бэкапа).

## После развёртывания

Первый запуск архитектора в проекте: он читает `AGENTS.md` — глобальный
(`~/.pi/agent/AGENTS.md`) и локальный (`<project>/AGENTS.md`) — а затем `memory/` проекта.
Если у проекта есть `memory/` (STATUS, DECISIONS, FROZEN, ISSUES, research/), архитектор
подхватит контекст автоматически и продолжит работу с того же состояния.
