# Migration from Existing Pi Make

## Keep

HTML/Tailwind, WordPress/PHP, Elementor, image generation, corpus/reference extraction, project memory, accessibility checks, Playwright/screenshot tooling, deterministic audits, WordPress preflight/deployment knowledge, and legacy agents as optional capabilities.

## Freeze as legacy

Mandatory Design Director -> Visual Director -> Composition Planner -> Image Director -> UI Coder chains; anti-template/uniqueness objectives; large planning JSON chains; visual gates that exist only to prove compliance with generated documents.

## Rebuild around Core

1. Project adapters
2. Runtime/preview manager
3. Screenshot + observation interface
4. Scoped edit loop
5. Persistent run state
6. Capability registry
7. Deterministic verification adapter

## First vertical slice

Support one simple HTML/Tailwind project:

prompt -> inspect -> build -> start runtime -> screenshot -> visual observation -> targeted edit -> screenshot -> verify

Do not implement WordPress, Elementor, corpus search, or complex multi-agent orchestration in the first slice unless required to prove the core contract.

## Acceptance

The vertical slice succeeds only if the second rendered version is demonstrably produced from an observation of the first rendered version.

A successful build without an edit loop is not a successful Core V1 test.
