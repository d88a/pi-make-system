# Onboarding — Сбор и структуризация контекста

Процедура для проектов, которые впервые переходят на работу через 
pi-харнес. Цель — собрать ВСЮ существующую информацию и создать 
структурированную память проекта.

## Шаги

### 1. Сканирование существующего контекста

```bash
# Найти все сессии pi
find /path/to/project -name "*.jsonl" -path "*/sessions/*"

# Найти документы
find /path/to/project -name "*.md" -not -path "*/node_modules/*"

# Понять структуру кода
find /path/to/project/src -type f -name "*.py" | head -50
```

### 2. Сбор информации от владельца

Попроси владельца вывалить ВСЁ что есть:
- История диалогов из браузера (Claude, ChatGPT)
- Заметки, документы
- Что помнит из головы
- Текущий статус проекта
- Какие направления активны, какие заморожены

**Не фильтруй на этом этапе** — собирай всё, даже если кажется мусором.

### 3. Структуризация

Создай файлы в `memory/`:

```
memory/
├── ARCHITECTURE.md    — текущая архитектура системы
├── STATUS.md          — что сделано, в работе, планы
├── DECISIONS.md       — лог решений с обоснованиями
├── FROZEN.md          — замороженные направления и почему
└── ROLES.md           — каталог ролей для этого проекта
```

#### ARCHITECTURE.md
```markdown
# Архитектура проекта

## Обзор
Краткое описание что это за проект.

## Компоненты
- Компонент 1: описание, расположение
- Компонент 2: ...

## Стек
- Python 3.12
- Redis
- ...

## Связи между компонентами
Как данные текут через систему.
```

#### STATUS.md
```markdown
# Статус проекта

## Текущий фокус
Что сейчас активно разрабатывается.

## В работе
- Задача 1: статус, кто работает
- Задача 2: ...

## Готово
- Что уже реализовано

## Следующие шаги
- Что планируется
```

#### DECISIONS.md
```markdown
# Лог решений

## YYYY-MM-DD: Решение X
- **Контекст**: почему возникла необходимость
- **Варианты**: что рассматривалось
- **Решение**: что выбрали
- **Обоснование**: почему именно это
```

#### FROZEN.md
```markdown
# Замороженные направления

## Направление 1
- **Когда заморожено**: дата
- **Причина**: почему заморозили
- **Статус**: что уже сделано, что осталось
- **Условие разморозки**: когда можно вернуться

## Направление 2
...
```

### 4. Проверка полноты

Пройдись по файлам и найди пробелы:
- Есть ли решения без обоснования?
- Есть ли активные задачи без статуса?
- Есть ли противоречия между файлами?

Задай уточняющие вопросы владельцу.

### 5. Создание AGENTS.md для проекта

```markdown
# Инструкции для архитектора проекта [имя]

## Контекст проекта
Краткое описание (2-3 предложения).

## Текущий фокус
Что сейчас в приоритете.

## Ограничения
- Не трогай FROZEN.md направления
- Данные лежат в /path/to/data
- ...

## Особенности работы
- Специфика этого проекта
- Ключевые файлы
```

### 6. Подтверждение

Покажи владельцу все созданные файлы. Дождись подтверждения 
или корректировок.

## Важно
- Не выдумывай — если информации нет, пометь "неизвестно"
- Разделяй факты и интерпретации
- FROZEN.md — критически важен для проектов с историей
- Лучше спросить лишний раз, чем предположить неправильно
