# Memory Guard Skill

Этот skill автоматически проверяет актуальность `memory/` файлов проекта.

## Когда запускать:

1. **После каждой завершённой задачи** (реализация, анализ, решение)
2. **После compaction** (когда контекст сжимается)
3. **Когда владелец спрашивает** "что сделано?" или "статус проекта"

## Протокол проверки:

### 1. Проверь наличие файлов:

```bash
ls -la memory/ 2>/dev/null || echo "memory/ не существует"
```

Если `memory/` не существует → создай базовую структуру:

```bash
mkdir -p memory
touch memory/STATUS.md memory/DECISIONS.md memory/FROZEN.md memory/ISSUES.md
```

### 2. Проверь актуальность STATUS.md:

```bash
stat -c "%y" memory/STATUS.md 2>/dev/null
```

Если файл не обновлялся >1 часа и были задачи → **НАПОМНИ**:

```
⚠️ Memory Guard: STATUS.md не обновлялся с <timestamp>.
Рекомендую запустить /save для актуализации.
```

### 3. Проверь консистентность:

Прочитай последние 3 записи из STATUS.md и DECISIONS.md.
Проверь что они не противоречат друг другу.

### 4. Проверь FROZEN.md:

Убедись что замороженные направления не были затронуты в последних задачах.

### 5. Проверь parseability (audit A-36):

Проверь что memory/ файлы не повреждены (битый markdown, ручные правки сломали структуру):

```bash
for f in memory/STATUS.md memory/DECISIONS.md memory/ROLES.md memory/ARCHITECTURE.md; do
  [ -f "$f" ] && { grep -q "^## " "$f" || echo "⚠️ $f: нет ни одного ## заголовка (битый?)"; }
done
```

Если файл повреждён (нет маркеров, нарушена структура таблиц):
- **НЕ перезаписывай** без понимания
- Восстанови из `.bak.<date>` если есть
- Иначе — перестрой из `observations.md` (сырые факты) + спроси владельца
- Зафиксируй инцидент в `ISSUES.md`

## Формат напоминания:

```
🧠 **Memory Guard**

Последнее обновление memory/:
- STATUS.md: <timestamp>
- DECISIONS.md: <timestamp>

Рекомендую: /save <описание что сделано>
```

## Автоматическое обновление (опционально):

Если модель поддерживает function calling, можно автоматически вызывать `/save` после каждой задачи.

Пример интеграции в AGENTS.md:

```markdown
## После каждой задачи:
1. Обнови memory/STATUS.md
2. Запиши в memory/DECISIONS.md (если было решение)
3. Проверь memory/FROZEN.md (не затронуты ли замороженные направления)
```

## Anti-patterns:

- **НЕ игнорируй memory/** — это приводит к потере контекста
- **НЕ забывай обновлять после compaction** — контекст сжимается, память остаётся
- **НЕ удаляй старые записи** — добавляй новые, сохраняй историю
